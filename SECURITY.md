# Security Policy

## Supported Versions

The current version of the **TEJAS-MK2 Calculator** is the supported version for security fixes.

Because this project is a client-side static web application, security issues may affect the HTML, CSS, JavaScript, dependencies, GitHub Pages deployment, or repository configuration.

## Reporting a Vulnerability

Please **do not disclose security vulnerabilities publicly in a GitHub issue** before they have been reviewed and addressed.

If GitHub Private Vulnerability Reporting is enabled for this repository, please use it to submit the report. Otherwise, contact the project maintainer privately through the contact method available on the repository's GitHub profile.

A useful vulnerability report should include:

- A clear description of the vulnerability.
- The affected file, component, or dependency.
- Steps to reproduce the issue.
- The potential security impact.
- Screenshots, proof-of-concept code, or logs when appropriate.
- Any suggested mitigation, if known.

Please avoid including passwords, authentication tokens, private keys, personal information, or other sensitive data in a report.

## Response Process

After receiving a report, the maintainer will:

1. Acknowledge and review the report when reasonably possible.
2. Attempt to reproduce and validate the issue.
3. Assess its severity and impact.
4. Develop and test a fix when necessary.
5. Publish the appropriate fix or mitigation.
6. Credit the reporter when they request attribution and it is safe to do so.

Response and remediation times may vary depending on the severity, complexity, and availability of the maintainer.

## Scope

Security reports may include issues involving:

- Client-side JavaScript behavior.
- Unsafe DOM manipulation or injection vulnerabilities.
- Dependency vulnerabilities.
- GitHub Actions and deployment configuration.
- Accidental exposure of credentials or sensitive configuration.
- Security-relevant repository configuration.

Purely cosmetic bugs, ordinary calculation errors, feature requests, and general usability issues should be reported through GitHub Issues instead.

## Responsible Disclosure

Please give the maintainer a reasonable opportunity to investigate and fix a vulnerability before publicly disclosing technical details.

Thank you for helping keep the project and its users safer.
